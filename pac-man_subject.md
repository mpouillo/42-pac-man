## I. Forewords

First released in 1980 by Namco, Pac-Man quickly became a cultural icon and one of the most influential video games of all time.

Designed by Toru Iwatani, its goal was to create a game that could appeal to women and casual players, contrasting with the space shooters of the era.

The game introduced the now-famous ghost AI, each with unique behaviors:

- Blinky chases.
- Pinky ambushes.
- Inky is unpredictable.
- Clyde is weird.

Pac-Man was also the first game to popularize the concept of a power-up - the Pacgum, also known as Power Pellets, that lets the player eat the ghosts.

The original arcade machine had 256 levels, but due to an integer overflow bug, level 256 was impossible to finish. This became known as the infamous "kill screen".

With this project, you will build your own modern version in Python, with modern structure and project organization, ready to be deployed on a real gaming platform.

## III. Common Instructions

### III.1 General Rules

- The project must be written in Python 3.10 or later.
- The project must adhere to the `flake8` coding standard.
- Functions should handle exceptions gracefully to avoid crashes.
  - Use `try-except` blocks to manage potential errors.
  - Prefer context managers for resources such as files or connections to ensure automatic cleanup.
  - If the program crashes due to unhandled exceptions during review, it will be considered non-functional.

  - Use context managers where possible for automatic handling.
- Code must include type hints for function parameters, return types, and variables where applicable, using the `typing` module.
- Use `mypy` for static type checking.
- All functions must pass `mypy` without errors.
- Include docstrings in functions and classes following PEP 257, using a style such as Google or NumPy, to document purpose, parameters, and returns.

### III.2 Makefile

Include a `Makefile` in the project to automate common tasks.

It must contain the following rules:

- `install`
  - Install project dependencies using `pip`, `uv`, `pipx`, or any other package manager of your choice.
- `run`
  - Execute the main script of the project, for example via Python interpreter.
- `debug`
  - Run the main script in debug mode using Python's built-in debugger, for example `pdb`.
- `clean`
  - Remove temporary files or caches such as `__pycache__` and `.mypy_cache`.
- `lint`
  - Execute:

```bash
flake8 .
mypy . --warn-return-any --warn-unused-ignores --ignore-missing-imports --disallow-untyped-defs --check-untyped-defs
```

- `lint-strict` (optional)
  - Execute:

```bash
flake8 .
mypy . --strict
```

## V. Detailed Specifications

### V.1 Usage

The program must be launched from the command line as follows:

```bash
python3 pac-man.py config.json
```

Requirements:

- It must take exactly one argument: a configuration file.
- The filename itself does not matter, but the file must be a JSON file.
- Any error must be handled cleanly with clear messages and never with a Python traceback.
  - Missing file.
  - Invalid value.
  - Missing key.

### V.2 Configuration File

The config file uses JSON.

In addition to the standard JSON format, comments must be handled:

- Lines starting with `#` are comments and must be ignored.
- Additional comment styles may also be supported, such as C or C++ comments.

The exact structure is up to the implementation, but keys must be documented in the README and robust defaults must be provided.

Suggested keys:

- `highscore_filename`
- `level` array of multiple levels
- `width`, `height` for each level
- `lives`: `3`
- `pacgum`: `42`
- `points_per_pacgum`: `10`
- `points_per_super_pacgum`: `50`
- `points_per_ghost`: `200`
- `seed`: `42`
- `level_max_time`: `90`

### V.3 Faulty Config Handling

On missing or invalid values:

- Clamp to safe defaults.
- Log a clear message.
- Continue running.

Unknown keys must be ignored.

There must be no traceback.

> Important: The game configuration will be updated during the defense.

### V.4 Maze Generator Integration

You must not write your own maze generator.

At project start, you are assigned an `A-Maze-ing` package from another group.

Requirements:

- Use their package as-is, without modifying it.
- The assigned package will be re-installed during peer review.
- Your loader must adapt to their interface, not the opposite.
- The parameter `PERFECT` will be set to `False` to produce Pac-Man-compatible corridors.
- If the generator fails, handle the error cleanly.

### V.5 Highscore System

Implement a persistent highscore system.

The exact implementation is up to you, but it must be documented in the README.

Requirements:

- Be stored as you choose, for example as a JSON file in the project or on disk.
- Be robust to file errors:
  - Missing file.
  - Invalid format.
  - Other file I/O problems.
- Handle player names:
  - Maximum 10 characters.
  - Alphanumeric characters and spaces only.
- Handle scores:
  - Non-negative integers.
- Keep the top 10 highscores, with player names and scores.
- Load highscores at game start.
- Save highscores at game end.
- Allow players to enter their name when they end the game, whether by winning or losing.
- Display highscores in the main menu.

## VI. Game Specifications

### VI.1 Level Structure

Each level must include:

- A maze with walls and corridors, generated by the assigned `A-Maze-ing` package.
- The first level is composed of a maze generated with a fixed seed, for example `42`.
- Each subsequent level is composed of a randomly generated maze.
- Pacgums, small dots, in most corridors.
- Super-pacgums, power pellets, in the 4 corners of the maze.
- 4 ghosts, one in each corner of the maze.
- The player starts in the middle of the maze.

### VI.2 Player

The player:

- Can move through corridors only, not through walls.
- Can move in 4 directions:
  - Up.
  - Down.
  - Left.
  - Right.
- Uses arrow keys or WASD, depending on keyboard support.
- Starts with 3 lives.
- Loses a life when touched by a ghost.
- Respawns in the middle of the maze after losing a life.
- Gets game over when all lives are lost.
- Wins the level when all pacgums are eaten.
- Wins the game when all levels are completed.
- Eating a pacgum increases the score by `X` points.
- Eating a super-pacgum, power pellet, increases the score by `Y` points and makes ghosts edible for a short time.
- Eating an edible ghost increases the score by `Z` points.

### VI.3 Ghosts

Ghosts:

- Move autonomously through corridors.
- Chase the player when not edible.
  - Chase behavior is up to the implementation, for example distance-based or random.
- Run away from the player when edible.
- Respawn to their corner after a while when eaten, for example after 5 or 10 seconds.

### VI.4 Pacgums and Super-pacgums

Pacgums:

- Are small dots placed in most corridors.
- Increase the score by `X` points when eaten.

Super-pacgums:

- Are larger dots placed in the 4 corners of the maze.
- Increase the score by `Y` points when eaten.
- Make ghosts edible for a short time.

### VI.5 Cheat Mode

Cheat mode:

- Can be activated to facilitate peer review.
- Must genuinely help the reviewer test all game features easily.

Suggested features:

- Invincibility:
  - No life lost.
  - Ghosts cannot eat the player.
- Level skip:
  - Immediately win the current level.
- Ghost freeze:
  - Ghosts stop moving.
- Extra lives:
  - Add extra lives to the player.
- Increased speed:
  - Player moves faster.
- Any other feature that may be useful.

### VI.6 Scoring

The score increases when:

- Eating a pacgum: `+X` points.
- Eating a super-pacgum: `+Y` points.
- Eating an edible ghost: `+Z` points.

The score does not decrease.

### VI.7 Game Progression

Requirements:

- The game consists of multiple levels, at least 10.
- Each level has a time limit, for example 90 seconds.
- If the time limit is reached, the behavior can be decided by the implementation, for example restart the level or end the game.
- If the player completes a level, they move to the next level.
- The player keeps their score and remaining lives between levels.
- The game ends when:
  - All levels are completed.
  - The player loses all lives.
- During the game, the player can pause and resume.
- When the game ends, win or lose:
  - The final score is displayed.
  - The player can enter their name to save the highscore.
- After the game ends, the player is returned to the main menu.

### VI.8 User Interface

#### Main Menu

The main menu must include:

- `Start Game`
  - Allows the player to start a new game.
- `View Highscores`
  - Displays the Top 10 scores with player names.
- `Instructions`
  - Shows game controls and rules.
- `Exit`
  - Closes the game application.

#### In-Game HUD

The HUD must always be visible during gameplay and show:

- Current score.
- Remaining lives.
- Current level.
- Remaining time for the level.

#### Pause Menu

The pause menu must include:

- `Resume the game`
  - Allows the player to return to the ongoing game.
- `Return to the main menu`
  - Allows the player to exit the current game and go back to the main menu.

#### Game Over Screen

The game over screen must:

- Display the final score.
- Prompt the player to enter their name to save the score in the highscores list.

#### Victory Screen

The victory screen must:

- Display the final score.
- Display a congratulatory message.
- Prompt the player to enter their name to save the score in the highscores list.
